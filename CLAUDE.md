# Kozmosz – project rules

Hungarian space-community website. Rust: Leptos 0.8 (islands mode) + axum, built with cargo-leptos.
Top priority: fastest possible load. These rules override any design skill or DESIGN.md
(design-taste-frontend, design-md, etc.) that suggests otherwise.

## Stack constraints
- Server-rendered HTML. Zero JavaScript by default. Interactivity only via `#[island]`, and every page
  that contains an island must be listed in `ISLAND_PAGES` (src/app.rs), otherwise it gets no WASM.
  The one exception is the ~120-byte inline `CLOSE_MENU_ON_LEAVE` script in `shell()` (closes the
  mobile menu before the page enters the back/forward cache; approved by the user 2026-10-08). Any
  other script needs the user's OK.
- Plain CSS in `style/main.css` (Lightning CSS minifies it, inlined into the HTML in production).
  No Tailwind, no Sass, no CSS-in-JS, no npm packages.
- Fonts: body text uses the system stack (`--font-body`). Headings use Urbanist, self-hosted as one
  Hungarian subset (`public/fonts/urbanist-hu.woff2`, ~17 KB, approved by the user 2026-10-08) with a
  metric-matched Arial fallback face. No other webfonts without the user's OK.
- Icons: Phosphor (regular) as inline SVG constants in `src/icons.rs`, rendered with `<Icon>`.
  No icon fonts, no CDNs.
- Design "Földi állomás" (ground station, chosen by the user 2026-10-08): cool near-black (#0a0c0f),
  hairlines framing real content, one accent (#ffde73, the "signal" colour), dark theme only. Shape
  rule: content frames (photos, panels, cards) are square; interactive controls (buttons, the nav bar
  and its current item, header chips, photo-page steps) are "Liquid Glass" soft rectangles
  (`--radius`, 12px; owner's requests 2026-10-08: translucent, blurred, specular rim, the primary
  one tinted yellow to amber; NOT pills, the owner rejected the pill shape), with solid
  fallbacks for prefers-reduced-transparency and browsers without backdrop-filter. The header is
  transparent: its chips float over the page. Monospace (system stack) only for real data: dates, times, frequencies, reception times.
  No em/en dashes in UI text. Design skills apply within these rules (dials: variance 6, motion 4,
  density 3; motion raised 2026-10-08 when the owner asked for "fancy": signature motion lives in
  page transitions, scrolling and hover, never in loops or load-time entrances). Mockups of the three candidate directions: D:\Claude\kozmosz-design-concepts.
- No third-party requests at runtime (no picsum, no CDN logos, no analytics) unless the user asks.
- Motion: CSS only (transform/opacity, `@view-transition`), always behind `prefers-reduced-motion`.
  Content must never start hidden (no opacity:0 waiting for JS). No looping animation; anything
  that moves on its own stops within 5 s (WCAG 2.2.2), like the hero's one satellite pass.
- Glass: `backdrop-filter` blurs only up to the nearest ancestor "backdrop root" (an element with
  `view-transition-name`, `filter`, `opacity` < 1, `mask`, `clip-path` or its own `backdrop-filter`).
  So `.site-header` carries no view-transition-name (its glass chips do), and a glass element
  nested in another glass element must be nearly opaque instead (the nav submenu).
- View transitions: a `view-transition-name` must be unique on a page, or the whole transition is
  skipped. Gallery tiles get the name `photo` only while hovered/focused/pressed or `:target`.
- Images: generated by `tools/images.py` (AVIF + JPEG per width, no metadata, GPS stripped) into
  `public/img/<key>-<w>.*` plus `src/images.rs`; reference them as `<Picture key=…>` or `kep:<key>` in
  content. `/img/*` and `/fonts/*` are cached immutable for a year: a changed file gets a new name.

## Pages
- Page texts live in `content/oldalak/*.md` (frontmatter + `##` sections, images as `kep:<key>`),
  parsed by `src/content.rs`. They are the club's own words: never paraphrase them silently; typo
  fixes need the user's OK (see content/README.md).
- New page: component in `src/pages/`, `<Route>` in `App` (src/app.rs), nav entry in `src/site.rs`.
- If its HTML is identical for every request, add the path to `STATIC_PAGES`: it is rendered once at
  startup and served from memory, precompressed (src/server.rs `PageCache`).
- The 404 page is also rendered once and cached, so `NotFound` must not depend on the request path.
- Calendar: `src/calendar/` downloads the club's public Google Calendar feed at startup and every
  10 minutes, then re-renders every cached page (so /programjaink stays current). Feed text is
  rendered escaped; attendee/organizer data and e-mail addresses are never shown.
- Drive galleries: `src/drive/` lists the `ALBUMS` folders at startup and every 10 minutes, downloads
  new photos and re-encodes them (AVIF + JPEG, no metadata) into `KOZMOSZ_DRIVE_DIR` (default
  `drive-cache/`, git-ignored): files in `files/<album>/`, served under `/drive/` (immutable: file
  names carry a content hash), `manifest.json` next to `files/` and never served (Drive IDs).
  `src/gallery.rs` builds each project gallery from the album, or from the Markdown images until the
  album has photos. Photo pages: `/projektek/<project>/kep/<slug>` (`src/pages/photo.rs`), rendered
  per request. Browsers never contact Google. Credentials (service-account key, API key) come from
  the environment only; never commit them.
- UI text is Hungarian. Code, comments and identifiers are English.

## Commands
- Dev (hot reload): `LEPTOS_HASH_FILES=false cargo leptos watch` → http://127.0.0.1:3000
  (watch only hashes its first build; with hashing on, CSS edits never reach the browser)
- Release: `cargo leptos build --release --precompress` (or `cargo leptos serve --release --precompress`)
- Tests: `cargo test --features ssr`
